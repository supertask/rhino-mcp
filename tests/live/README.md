# 実機確認（本物の Rhino を使う）

`rhino_live_check.py` は、本物の Rhino 7 を起動して、通信まわりと Rhino の各ツールを確認するスクリプトです。ファイル名が `test_` で始まらないので、①②の自動テストを実行しても動くことはありません。

## 実行のしかた

Rhino を閉じた状態で、リポジトリのフォルダから実行します。

```bash
uv run python tests/live/rhino_live_check.py
```

Enter を押すたびに 1 項目ずつ進みます。止めずに最後まで実行したいときは `--yes` を付けます。

| オプション | 内容 |
|---|---|
| `--yes` | Enter を待たずに全部実行する |
| `--run-bridge` | Rhino の起動時に `rhino_mcp_bridge.py` を実行させる（起動時の自動実行を設定していない場合） |
| `--verbose` | MCP 側の動作ログも表示する（既定では結果だけを表示） |
| `--rhino-exe <パス>` | Rhino.exe の場所（既定は `C:\Program Files\Rhino 7\System\Rhino.exe`。環境変数 `RHINO_EXE` でも指定可） |

## 安全のための決まり

- **Rhino がすでに起動していたら、何もせずに終了します。** 作業中のデータに触れないためです。
- Rhino は新規の空ドキュメントで起動し、終わったら**保存せずに閉じます**。
- 途中で 1 回、Rhino を終了して起動し直します（再起動からの復帰を確かめるため）。

## 確認する項目

1. 接続が強制的に切れても、Rhino のコマンドラインにエラーが出ず、ログファイルにだけ記録される
2. Rhino を再起動しても、最初の操作が 1 回で成功し、二重に実行されない
3. 処理中の切断やタイムアウトがあっても、操作は 1 回しか実行されない（Codex には「自動では再送していません」と返る）
4. Codex が使う 5 つのツールが動き、日本語がそのまま読める
5. 想定外のエラーやおかしな入力でも止まらない
6. MCP ライブラリが 1 系である
7. Rhino を閉じているときに「Rhinoに接続できません…」と表示される

結果は「✔ 合格 / ✖ 不合格 / △ 既知の問題」で表示されます。終了コードは、不合格がなければ 0、あれば 1 です。

## 実行中に表示されるメッセージ

- Rhino を終了させたときにターミナルに出る `Connection lost after sending execute_code; not retrying: timed out` は、Rhino が返事をする前に閉じたためで、問題ではありません。
- `--run-bridge` を付けたうえで起動時の自動実行も設定している場合、Rhino に「ポート9876は…起動を中止します」と出ます。ブリッジが 2 回読み込まれたためで、問題ではありません。
- この確認スクリプトを実行すると、Rhino の `rhino_mcp.log` に記録が追加されます。
